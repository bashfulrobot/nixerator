# token-optimizer

Why the token-optimizer Claude Code plugin needs NixOS-specific plumbing, which
of its behaviours are deliberately suppressed, and what to check when bumping it.

Upstream: [alexgreensh/token-optimizer](https://github.com/alexgreensh/token-optimizer).
Pinned at v5.11.65 (`5c0af3bf9dc92f7d548ef211bde39a8a01ac03e1`), added 2026-07-25.

## Where it lives

| Concern | File |
|---|---|
| Marketplace SHA pin | `modules/apps/cli/claude-code/cfg/plugin-config.nix` |
| NixOS plumbing (tmpfiles rule, config flags) | `modules/apps/cli/claude-code/cfg/token-optimizer.nix` |
| Wiring (`hasTokenOptimizer` gate, `systemd.tmpfiles.rules`) | `modules/apps/cli/claude-code/default.nix` |
| Activation splice | `modules/apps/cli/claude-code/cfg/activation.nix` |
| Host enablement | `modules/suites/ai/default.nix` (workstations only) |

Everything is gated on the plugin id appearing in `apps.cli.claude-code.plugins`,
so dropping the id from the list removes the tmpfiles rule and the activation
step along with it. Headless `srv` deliberately does not run it.

## The interpreter problem

`hooks/python-launcher.sh` refuses any Python outside a hardcoded allow-list:

```
_SAFE_PREFIXES="/usr/bin /usr/local/bin /opt/homebrew/bin /opt/homebrew/opt /home/linuxbrew/.linuxbrew/bin"
```

On NixOS `python3` is at `/run/current-system/sw/bin/python3` and `/usr/bin`
contains only `env`, so all 24 hooks exit 127 with
`token-optimizer: no usable Python 3 interpreter found`.

There is no way around it from configuration. The launcher has no interpreter
env var, and the `TOKEN_OPTIMIZER_PY_CACHE` fast path re-runs `_is_safe_prefix`
on the cached value, so a cache entry cannot smuggle a store path in either.

The fix is a `systemd.tmpfiles` rule planting a root-owned symlink:

```
L+ /usr/local/bin/python3 - - - - ${pkgs.python3}/bin/python3
```

`_is_safe_prefix` matches on the literal path string and never resolves the
link, so the store path behind it does not matter, and `L+` re-points it on
every nixpkgs bump. `/usr/local` does not otherwise exist on NixOS, so nothing
contends for it — but note this does put an FHS `python3` on the host for any
other tool that goes looking, which is the one genuine cost of the approach.

This is also why the integration is not purely home-manager: `/usr/local` is
root-owned and unreachable from a user activation script.

## Behaviours suppressed on purpose

Left alone the plugin writes into state this module owns. Three flags in its
`config.json` turn each off at the source, merged in by activation on every
rebuild so a runtime toggle cannot drift them back:

| Flag | Stops |
|---|---|
| `quality_bar_disabled` | Claiming the settings.json `statusLine` slot with an absolute path into its own versioned plugin cache, plus the "stale path" self-heal that rewrites it on every upgrade. `statusline.sh` stays authoritative. |
| `daemon_disabled` | Silently writing and `systemctl --user enable --now`-ing `token-optimizer-dashboard.service` at SessionStart, and its loopback listener on 127.0.0.1:24842. |
| `enterprise_consent_shown` | Nothing — this one is *granted*. Every hook no-ops until consent is recorded, so without it the plugin installs and does nothing. |

Flipping `daemon_disabled` to `false` in `cfg/token-optimizer.nix` and
rebuilding is the supported way to opt into the dashboard. Declaring the unit
in home-manager instead is a dead end: the server script is generated by
`measure.py` into a plugin-cache path that does not exist until first run and
moves on every version bump.

The file is at
`~/.claude/plugins/data/token-optimizer-alexgreensh-token-optimizer/config/config.json`.
It must stay a real, writable file — `plugin_env._is_safe_subdir` rejects
symlinked paths, and `hooks/run.py` treats a symlinked `config.json` as absent
and fails open, which would silently discard every flag above.

One more runtime write is left alone: the plugin sets `cleanupPeriodDays` to
99999 only when the key is missing, and `config/settings.json` already declares
15. That wins, so nothing drifts — at the cost of bounding the plugin's trend
history to 15 days of transcripts. Raise that number if the trend analysis is
the reason you want it.

## Bumping

Same as any pinned marketplace: find the new HEAD, update the SHA in
`cfg/plugin-config.nix`, rebuild.

```bash
git -C ~/.claude/plugins/marketplaces/alexgreensh-token-optimizer rev-parse origin/main
```

After a bump, re-check `hooks/python-launcher.sh` for changes to
`_SAFE_PREFIXES` (an added `/nix/store` entry would make the tmpfiles rule
redundant) and grep `measure.py` for new unconditional writes to
`~/.claude/settings.json` or `~/.config/systemd/user/`.
