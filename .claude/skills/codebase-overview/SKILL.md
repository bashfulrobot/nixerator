# nixerator: codebase overview

Personal NixOS + home-manager flake for three hosts. This file is the map and
the router. It carries structure and entry points only — no option values, no
file contents. Detail lives in the topic files it points at.

## Directory map

| Path | What it holds |
|---|---|
| `flake.nix` | Inputs, the three `nixosConfigurations`, `formatter` output. Reads `settings/globals.nix` + `settings/versions.nix`, then calls `lib.mkHost` per host. |
| `lib/` | `default.nix` (re-exports `mkHost` only), `mkHost.nix` (the host builder), `mkWebApp.nix` (webapp module factory), `secrets.nix` (runtime-materialization helper). |
| `settings/globals.nix` | User identity, paths, defaults (stateVersion/timezone/locale), preferences, AI defaults, remoteEdit, git, per-host network identity. |
| `settings/versions.nix` | Centralized version pins, keyed `cli.*`, `gui.*`, `fish-plugins.*`. |
| `modules/` | Every module. Auto-imported by `modules/default.nix`. |
| `modules/archetypes/` | `workstation`, `claudeWorkHost` — top of the cascade. |
| `modules/suites/` | 12 feature bundles that mostly just enable other modules. |
| `modules/apps/{cli,gui,webapps}/` | Per-app modules. |
| `modules/{system,server,dev}/` | System services, server services, dev environments. |
| `modules/archive/` | Retired modules, excluded from auto-import, original relative path preserved for a `git mv` back. |
| `hosts/<host>/` | Per-host config. See "Host wiring". |
| `justfile` | The only sanctioned build/rebuild/lint/format/secrets interface. |
| `.githooks/pre-commit` | Auto-formats staged `.nix` via `nix fmt` and re-stages. Install once per clone with `just setup-hooks`. |
| `.github/workflows/` | `ci.yml` (autofix: nix fmt, statix, deadnix, shfmt, fish fmt, then signed-API commit) and `update-flake-lock.yml`. |
| `extras/docs/` | Deep-dive reference, one `.md` per topic, plus `index.html` (`just docs`). |
| `extras/helpers/`, `extras/scripts/` | Bootstrap/secret-fetch shell helpers; package-update and security-alert checkers invoked by `just rebuild`. |
| `dank-profiles/` | Captured DankMaterialShell settings, shared across workstations. |
| `docs/plans/`, `docs/superpowers/` | Historical design/implementation plans. Not live config. |
| `.planning/` | Agent planning state scoped to the `worktree-flow` module. Not repo-wide. |

**Directories a change usually touches together**

- New app: `modules/apps/<kind>/<name>/default.nix` + an enable in either a
  suite under `modules/suites/` or `hosts/<host>/modules.nix` + (if the package
  is built locally) `modules/apps/<kind>/<name>/build/` and a pin in
  `settings/versions.nix`.
- New host: `flake.nix` (`mkHost` entry) + `hosts/<host>/`.
- Behaviour that must hold on every host: `modules/` + `lib/mkHost.nix`
  (assertion), not an import in both places.

## Module anatomy

Auto-import: `modules/default.nix` calls `inputs.import-tree.filterNot` over
`modules/`. Excluded by infix match: `/disabled/`, `/build/`, `/cfg/`,
`/reference/`, `/archive/`, plus anything containing `/_` (import-tree's own
default). Never hand-import a module — one exception below.

Standard shape:

```nix
{ lib, pkgs, config, ... }:
let cfg = config.<namespace>.<name>;
in {
  options.<namespace>.<name>.enable = lib.mkEnableOption "...";
  config = lib.mkIf cfg.enable { ... };
}
```

- Namespace mirrors the directory path: `apps.cli.*`, `apps.gui.*`,
  `apps.webapps.*`, `suites.*`, `system.*`, `dev.*`, `server.*`,
  `archetypes.*`.
- `specialArgs` / `extraSpecialArgs` supplied by `lib/mkHost.nix`: `inputs`,
  `hostname`, `globals`, `versions`, `secrets`, `secretsLib`.
- Locally-built packages live in the module's own `build/` subdir and are
  pulled in with `pkgs.callPackage ./build { inherit versions; }`; the
  derivation reads its pin from `versions.<kind>.<name>`.
- Home Manager config goes inside `home-manager.users.${globals.user.name}`.
- Webapps are generated by `lib/mkWebApp.nix`, imported by relative path from
  inside the webapp module (it is not re-exported through `lib/default.nix`).

**Wiring a new module so it is actually evaluated.** Dropping the file under
`modules/` is enough for donkeykong and qbert, which import `../../modules`.
It is *not* enough for srv, which hand-imports every module path in
`hosts/srv/modules.nix`. A module needed on srv requires both the import path
and the enable. Details and the enable-option conventions: `modules/CLAUDE.md`,
`modules/suites/CLAUDE.md`, `extras/docs/module-development.md`.

**The one hand-import exception**: a host-wide invariant with no enable option
(currently `modules/system/linger`). Import it from exactly one place per host
and enforce reachability with an assertion in `lib/mkHost.nix` — assertions
merge, imports do not. See `.claude/docs/user-lingering.md`.

## Host wiring

All three go through `lib.mkHost` in `flake.nix`, which composes
`hosts/<host>/configuration.nix`, the home-manager NixOS module, a shared
nixpkgs/overlay/gc block, the linger assertion, and per-host `extraModules` /
`homeManagerModules`.

Per-host files: `configuration.nix` (imports, networking, archetype),
`modules.nix` (module enables and host-specific option values), `home.nix`,
`hardware-configuration.nix`, plus optional `boot.nix`, `disko.nix`, `gpu.nix`
and host-specific one-offs. Do not mix the configuration.nix / modules.nix
roles.

What actually differs:

| | donkeykong | qbert | srv |
|---|---|---|---|
| Role | laptop, often off | desktop, usually up | headless server, always on |
| Module import | `../../modules` auto-import | `../../modules` auto-import | hand-imported paths in `modules.nix` |
| Archetypes enabled | `workstation` | `workstation` + `claudeWorkHost` | `claudeWorkHost` only |
| `extraModules` | disko, hyprflake, nixos-hardware (T14 gen6) | disko, hyprflake | none |
| `homeManagerModules` | spicetify | spicetify | none |
| User/packages | via modules | via modules | declared inline in `configuration.nix` |

More: `hosts/CLAUDE.md`, `extras/docs/hosts.md`, `extras/docs/adding-hosts.md`.

## Rebuild pipeline

**Raw nix commands are forbidden in this repo. The justfile is the interface.**
`just` derives the target from `hostname` (`host_flake := ".#" + hostname`), so
recipes always mean "the host I am on" unless the recipe names one.

Order inside a switch recipe (`rebuild`, `quiet-rebuild`, `quiet-upgrade`):

1. `secrets-nudge` — local mtime check, `secrets.json.tpl` vs the rendered
   cache. No network. Warns, does not block.
2. `pre-rebuild` — captures live DMS settings on any workstation; captures live
   Claude Code / Agent OS state into the repo on qbert only.
3. `sudo nixos-rebuild switch --impure --flake <host>`, output to
   `/tmp/nixerator-rebuild.log`.
4. `post-rebuild` — `just update-skills`, DMS service bounce (skipped when the
   screen is locked), capture diff surfaced for review.

Recipe map:

| Need | Recipe |
|---|---|
| Rebuild this host, agent-friendly | `just quiet-rebuild` (`qr`) |
| Rebuild this host, interactive | `just rebuild` (`r`) |
| Verify another host evaluates and builds, without activating | `just build-host <host>` |
| Rebuild against a local hyprflake checkout | `just hyprflake-test` (`hft`) |
| Upgrade all inputs | `just quiet-upgrade` (`qu`) |
| Re-lock one input | `just update <input>` |
| Lint | `just health` (deadnix + statix) |
| Format | `just fmt` |
| Capture live state into the repo, ad hoc | `just capture` |
| Resolve a capture conflict | `just capture-resolve <relpath> --home\|--repo` |
| Rebuild/upgrade a peer over SSH | `just remote-rebuild` (`rr`) / `just remote-upgrade` (`ru`) |
| Generations / rollback | `just generations` (`gen`) / `just rollback` (`rb`) |
| Visual repo tour | `just docs` |

`just default` lists everything. Failure handling, the push-to-main behaviour
of the lock-bumping recipes, and the git rules: `.claude/docs/conventions.md`.

## Secrets (structure only)

Never read, print, or quote a rendered secret value — not a prefix, not a
length. `~/.config/nixos-secrets/` and `~/.config/op/` are on Claude Code's
Read deny list, and a PreToolUse guard denies shell reads of them too.

Mechanism: 1Password (`op inject`); git-crypt is retired.

- Template: `secrets.json.tpl` at the repo root — `op://` references and
  placeholders, no values.
- Render step: `just render-secrets` (`rs`) writes
  `~/.config/nixos-secrets/secrets.json`, outside the repo and outside the Nix
  store. `just push-secrets <hosts>` (`ps`) scp's it to allow-listed peers;
  `just check-secrets` (`cs`) diffs live 1Password against the cache.
- Eval side: `flake.nix` reads that path as a *string* (not a Nix path
  literal), so it is never copied into the store as a flake input, and passes
  the parsed attrset to every module as `secrets`.
- Runtime side: `lib/secrets.nix` exposes `installValue`, the one helper for
  writing a value to disk at activation without it entering eval or the store.
  It is value-free by construction.
- Guard optional keys with `lib.optionalAttrs (secrets.foo or null != null)`.

Full flow, vault item table, rotation, per-host setup: `extras/docs/secrets.md`.

## Where to start reading

| Change | Start at |
|---|---|
| Add/modify a CLI or GUI app | `modules/apps/<kind>/<name>/` + `modules/CLAUDE.md` |
| Add a locally-built package | an existing `modules/apps/cli/*/build/` + `settings/versions.nix` |
| Change what a host gets | `hosts/<host>/modules.nix` |
| Change what every workstation gets | `modules/archetypes/workstation/` then the suite |
| Add a host | `flake.nix` + `extras/docs/adding-hosts.md` |
| Change a shared default or path | `settings/globals.nix` |
| Change the build/rebuild flow | `justfile` |
| Understand an eval failure | `/tmp/nixerator-rebuild.log` via a Nix subagent, not the main context |

| Three hosts, their `extraModules` / `homeManagerModules` | `grep -n 'lib.mkHost' -A12 flake.nix` |

| Rebuild step order | the `rebuild` / `quiet-rebuild` recipe bodies in `justfile` |

| srv still hand-imports rather than auto-importing | `grep -n 'modules' hosts/srv/configuration.nix` |

Do not run a rebuild, an upgrade, or a raw nix command to verify any of the
above — every check here is a read.
